## What changed

### Worker (`dana-worker/`, runs on the editing computer)

| Area | What it does now | File |
|---|---|---|
| Colour | measures exposure, contrast, colour cast, saturation and the face area on frames of the cut; corrects only what is outside the working ranges; re-measures the skin tone and backs off when it moves; never corrects an already corrected picture | `adjust.py` |
| Sound | measures the background only between the spoken words; high-pass and at most 6 dB noise reduction, only when measured; checks that the speech level did not move; loudness to −14 LUFS as before | `adjust.py` |
| Caption animation | a card can fade in (and rise) over 0.12 s; the frame-by-frame on-screen check understands the fade | `captions.py`, `checks.py` |
| Motion graphics | the plan may add an opening title and / or a key-phrase emphasis, only with a stated job and only as an exact quotation; rendered by HyperFrames to transparent frames and overlaid; checked on the finished file | `motion.py`, `story.py` |
| Before / after | three stills (same frames) and a side-by-side clip in every package | `adjust.py`, `run.py` |
| Switches | colour, sound cleanup, zooms, caption animation and graphics can each be turned off per project | `adjust.enabled` |
| Free-text request | a tool-free model call turns the owner's note into named areas and structured changes; only those are applied and the revision stays locked to the previous plan; a request about the content itself is re-planned and says so | `interpret.py` |
| Corrections reach derived text | a corrected card also corrects the cover quote, a graphic's text and the caption draft where they contain it (a short word is never replaced blindly in free text) | `story.correct_derived` |
| Review by category | 12 categories, fixed criteria, rubric version; each criterion is measured / stills / model / "needs you"; undecided = "not checked", never a mark; improvements by importance, technical defect vs. creative preference, and whether Dana can apply them | `review.py` |
| Review of an uploaded edit | measures the file, a tool-free model reads its transcript and stills, same rubric; says whether captions are burned in | `review_only.py` |
| "Apply improvements" | on Dana's own edit: same plan, the editor may act on the findings. On an uploaded edit: the owner's cut is kept whole, no zoom, no graphic, no second caption layer; only technical improvements | `run.py` (`apply_review`, `polish`) |
| Reference analysis | adds structure / message, pauses, transitions, motion graphics, colour and sound measured along the whole video, what fits our content, and a coverage block (frames sampled, what was not done) | `reference.py` |

### Server (`services/dana_studio.js`, `services/dana_references.js`, `routes/dana_studio_routes.js`, `utils/dana_brand.js`)

- `POST /projects/:id/captions/verify` — "אמת ושמור תיקון": one caption, after listening. Stored on the project with the
  transcript's original text beside it; states `unchecked / corrected / verified`; drops an approval; renders nothing.
  The next version is produced when the owner asks, and every later job carries the corrections.
- Progress: when each stage really started is recorded; the view returns the phase (transcribe → analyse → plan → edit →
  review → fixes → ready), elapsed time, time since the worker's last update, and a percentage that is an **estimate**
  from the measured stage times of earlier edits and is labelled so. No percentage in a correction round. 100 only when
  the package is there.
- Review-only projects (`kind: review_only`): a `review` job, the uploaded file is the video, no approval or publishing.
- `POST /projects/:id/apply-review`, `PATCH /projects/:id/settings` (connected account, adjustment switches).
- `POST /references/compare`, `POST /profiles/combined` — a combined profile where each number names the reference it was
  taken from; versioned; a default only when the owner says so.
- `pilates_barre_power` is listed as a connected, verified account (the read-only probe of 2026-11-15) and can be chosen
  per project. A verified connection is not a permission to publish.

### Page (`public/dana-studio.html`, `public/dana-studio.js`) — rewritten

Home: projects (two upload actions: raw footage / an edited video for Dana's review), **references and editing style**,
brand and account, standing rules. A project: the player and "the next action" stay in view; six steps —
project → transcript → style and references → edit → Dana's review → watch and approve. On a phone the player is small
and sticky and the main action sits in a bottom bar.

## What is NOT there (do not present as active)

- **B-roll / cutaways**: nothing was built; there is no cutaway footage to work with.
- Word-by-word (karaoke) caption animation; explanatory graphics (charts, diagrams); music; sound effects.
- Nobody and nothing listens to the audio or watches motion. Whether the cleanup sounds natural, whether a zoom feels
  right and whether the colour looks right are the owner's checks; the before / after material exists for that.
- A correction of text that is burned into the source picture cannot change the picture, and the page says so.
- The rating is a count of fixed criteria. It is not a quality score and not a prediction of performance.
- Learning from repeated corrections across projects happens only through a rule the owner marks as standing.
- The analysis of a reference cannot see caption animation, the kind of a transition, or hear music: hypotheses.
- Not tested on a real phone or against production. The phone check is a 390×844 headless browser.
- `tests/dana_tab_browser_check.mjs` still checks the panel's Dana tab; its sections that walked the old page layout are
  switched off (`LEGACY_LAYOUT`) and replaced by `tests/dana_studio_page_check.mjs`.

## Commit and deployment plan (nothing is deployed)

What would be deployed is the commit this document is part of (see `git log`). Production runs `7166b2b`.

Order matters, because the new worker uploads two artifacts the old server refuses, and the old worker does not know
review jobs:

1. Stop the editing worker (`STOP` file in `C:\Users\owner\dana-work`, or Ctrl+C).
2. Deploy the server: `railway up --detach` from the repository root. `dana-worker/` and `data/` are not uploaded.
   No new environment variable. Existing `studio.json` is read as is (new fields are optional).
3. Verify: `/health` 200; `GET /api/dana/studio/status` → `publishingEnabled: false`, `notifications: "mock"`,
   `accounts` lists `pilates_barre_power`; the page opens and old projects still open.
4. Start the worker with the new code (`python -X utf8 dana-worker\worker.py --config …production.json`). It needs the
   `hyperframes` CLI on PATH (installed: 0.9.26); without it graphics are reported as not added and the edit completes.
5. One upload from the phone, and one edited video for review.

Rollback: stop the worker; `git checkout 7166b2b && railway up --detach`; start the worker from that checkout. Projects
made by the new version stay on disk; the old page shows them without the new sections. A version produced by the new
worker is a normal package for the old server. Kill switches are unchanged (`DANA_WORKER_TOKEN`, `STOP`).

Still requires the owner, separately: any deployment, turning on real notifications, any publishing or upload to Meta.
