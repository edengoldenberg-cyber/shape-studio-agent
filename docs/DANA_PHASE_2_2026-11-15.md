## Why version 1 was a technical edit only

- The server stored `adapter: 'heuristic'` for every upload that did not name an adapter and sent it with the job.
  Only the local test scripts asked for the model (`options.adapter: 'claude'`). A panel upload therefore always
  ran the speech-density rule: no message, no brief, no review cycles.
- The worker configuration had the model adapter enabled, but a job's adapter overrode the configuration.
- Fix: the worker configuration decides (`judgement.adapter`, `judgement.job_adapters_allowed`); the server
  stores no default adapter. When the model is unavailable the job **fails clearly**
  (`judgement.on_model_failure: "fail"`); the optional `fallback_marked` mode produces a package labelled
  `judgement_mode: fallback_heuristic`, which the server refuses to approve without a recorded exception.

| Stage | What it does | Basis |

| second listening | second transcription pass of the source | Whisper large-v3, no silence filter |
| content plan (`story.py`) | message, opening, parts with source times, what was left out, brief, zoom moments, cover, word doubts, burned-text detection | model, tool-free: transcript + measured loudness per word + source stills. It does not hear audio or see motion |
| assemble | joins several parts, hard picture cut, 25 ms audio fade each side | ffmpeg; cuts checked against word times |

| package | `plan`, `zooms`, `transcript` (doubts, corrections), `caption_position`, `rules_used` (skill text + hash, profile + hash) | — |

## Not implemented (do not present as active)

- Analysis of a reference video and a proposed profile from it. References can be stored with a note; they stay
  "awaiting analysis".
- Learning repeated corrections across videos. Corrections are kept per project only.
- Brand settings other than the destination account from the page.
- A designed cover with text through the API (needs a public URL; owner decision, unchanged).
- Music / sound design. Not part of this pipeline.
- The owner's transcript corrections are applied to the working transcript by source time; the second
  transcription of the final audio will still write what it hears, so a corrected word can appear as a text
  difference in the checks. It is listed for the owner, not hidden. Substituting the owner's correction into
  that check is not implemented.

## Open decision that limits "large" captions

The working safe zone keeps the right 230 px clear for the whole height (the strictest reading of the installed
skill's numbers, not measured against the Instagram app). Centred text is therefore at most 620 px wide, which
is why 96 px captions break into two short lines. Widening it for the centre band is the owner's decision
(`reels_safe_zone.json → right_clear_from_y`); it was not changed.

## Added and run end to end locally (`scripts/dana_e2e_phase3.cjs`, 22 checks passed)

1. **Reference analysis is real.** A reference video + note → the worker measures cuts (scene detection), speech pace
   (transcription) and changes of face size inside a shot, shows stills to the model, and returns per-aspect
   observations with example times, each labelled *measured / seen in stills / hypothesis* (sound is always a
   hypothesis), what not to imitate, open hypotheses and a **proposed** profile (numbers clamped to fixed ranges +
   style rules). Nothing becomes a default before the owner approves; approval creates a versioned profile that
   names its reference. A new project was then planned, rendered and reviewed with that profile, and its package
   says so (`rules_used.profile`, `references`, `profile_rules`).
   - Only uploaded files can be analysed (the worker has no network access). Links are stored as `link_only`.
   - The numbers a model reads from stills are not stable: two analyses of the same clip proposed caption sizes
     84 and 110. They are a starting point for the owner's eye, which is why every number is editable before approval.
2. **Standing rules.** A note marked "standing rule" becomes one rule with id, version and source (project,
   version, who, when); the next project's job carried it and its package lists it. A project-only note is not a rule.
3. **Owner corrections survive the second transcription.** Inside a corrected span the owner's words replace
   what the re-transcription heard, in both alignment and the checks; a disagreement is shown as information
   (`owner_correction_kept`) and opens no new item.
4. **A revision without a note is locked to the previous plan.** No planning call is made; parts, message, the
   other zooms, the other cards, the caption text and the cover are identical; only the requested change differs.
   A revision WITH a note is re-planned (the previous plan is given as context) and may change more.
5. **Quality is reported in three groups** — automatic technical checks, the model's content assessment (on text
   and stills, explicitly not proof of quality), what needs the owner's viewing/listening — plus a list of what
   was not verified. No single score.

## Remaining gaps

- A revision with a note can still change things that were not asked for.
- Context doubts raised by the model in version 1 are not carried into a locked revision (low-confidence and
  second-pass doubts are recomputed).
- A locked revision does not let the editor apply reviewer findings; blocking ones go to the owner.
- Reference analysis: music / sound and motion feel are never measured; zoom detection is a face-size proxy.
- Repeated-correction learning across videos is not implemented (by the owner's caution rule, corrections stay
  per project).
- Not tested on a real phone or against production.
