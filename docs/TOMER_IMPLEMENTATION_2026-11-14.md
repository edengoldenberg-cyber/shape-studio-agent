## 3. מה תומר עושה עם הודעת חבר/ה

כל הודעה מסתיימת באחת מאלה: תשובה מאומתת מ-Arbox · שאלת הבהרה אחת · פנייה שמורה + התראה אחת למנהל · שתיקה מכוונת (תודה, אימוג׳י) שנרשמת ביומן.

- **הודעה חוזרת באותו נושא** מצטרפת לפנייה הפתוחה (בלי פנייה שנייה ובלי התראה שנייה) ומסמנת אותה "הודעה חדשה מהחבר/ה".
- **נושא אחר** = פנייה נפרדת עם התראה משלה.
- בקשה לא ברורה כשיש פנייה פתוחה מהיממה האחרונה — מתווספת לפנייה ומקבלת אישור קצר; לא נזרקת.
- **חבר/ה שכותב/ת בזמן שהצוות מחזיק בשיחה** — תומר שותק, וההודעה מתווספת לפנייה הפתוחה.
- פרטים חסרים (למשל תאריכי הקפאה) אינם תנאי לפתיחת הפנייה; אפשר להוסיף אותם אחר כך.
- הנוסחים קבועים בקוד ואומרים רק "רשמתי פנייה לצוות" — לא "העברתי" ולא "יחזרו אליך".
- תשובות תומר נשלחות מיד גם בשעות השקטות (הוא רק עונה למי שכתב). המסלול המשותף היה שולח "נחזור אליך מחר בבוקר" ושומר את התשובה בתור בזיכרון שאתחול מוחק. `TOMER_QUIET_HOURS=true` מחזיר את ההתנהגות המשותפת.

## 4. התראה למנהל

- נמען **אחד**: `TOMER_MANAGER_PHONE`, ואם לא הוגדר — בעל/ת הסטודיו ב-`staff_config.json`.
- תוכן: סוג הבקשה, שם, טלפון + קישור וואטסאפ, ציטוט ההודעה, תאריכים מבוקשים, נתוני Arbox, "לא בוצע שינוי ב-Arbox", וקישור ישיר לפנייה: `…/#tomer/case/<id>`.
- מצבים: `pending` · `accepted` (ספק הוואטסאפ קיבל — לא הוכחת קריאה) · `failed` · `uncertain` (הבקשה יצאה ולא התקבלה תשובה — אולי הגיעה).
- ניסיון חוזר מהפאנל: `failed` ← שליחה; `uncertain` ← רק "שלח שוב בכל זאת" (אזהרת כפילות); `accepted` ← לא נשלח דבר. לחיצה כפולה לא שולחת פעמיים.
- **אתחול / פריסה לא משחזרים התראות.** התראה שנקטעה באמצע ← `uncertain`; שלא התחילה ← `failed`. שתיהן מוצגות בפאנל להחלטת הצוות.

## 5. הפאנל (לשונית "תומר" ← "פניות")

- **מונים** (גם מסננים): כל הפתוחות · פתוח — ממתין לצוות · בטיפול · ממתין לחבר/ה · נסגרו. מחושבים מהפניות השמורות. כשהטעינה נכשלת מוצג "—" ושגיאה עם "נסו שוב" — לעולם לא 0.
- **מסך פנייה**: זהות (שם, מזהה Arbox, טלפון, וואטסאפ) · קטגוריה, עדיפות, סטטוס, אחראי/ת, נפתחה / עודכנה, הצעד הבא · הבקשה · מצב ההתראה + ניסיון חוזר · נתוני Arbox עם מקור ושעת קריאה, ומצב "Arbox לא זמין" מפורש · השיחה המלאה עם תיוג מי כתב (חבר/ה / תומר / צוות — שם) · מי עונה כרגע · היסטוריית אירועים.
- **פעולות**: שיוך · שינוי סטטוס · הודעה לחבר/ה בשם הצוות (מעבירה את השיחה לצוות ונרשמת כהודעת צוות) · קח את השיחה / שחרר לתומר · קריאה מחדש מ-Arbox · סגירה עם תוצאה והערת סיכום (חובה) · פתיחה מחדש.
- אין כפתור לביטול / הקפאה / רישום — המערכת לא מבצעת אותם.
- לשונית "היום" מציגה את אותם מונים ואת הפניות שדורשות תשומת לב; לשונית "שיחות" מקשרת לפנייה הפתוחה.
- תוקן: הודעת החבר/ה נרשמת לפני תשובת תומר, כך ששיחה שנענתה לא מופיעה עוד כ"לא נענתה".

## 6. הזדהות (`middleware/auth.js`)

- הכול מוגן חוץ מ: webhooks של ספקים, `/health`, `/api/version`, קישור ה-ics, ותמונות מערכת השעות (קריאה בלבד).
- בלי `DASHBOARD_PASSWORD` הלוח נעול (503) — לא נחשף בטעות.
- סשן: עוגייה חתומה, HttpOnly, SameSite=Lax, Secure בייצור; תוקף 7 ימים (`SESSION_TTL_HOURS`). **יציאה מבטלת את הסשן בשרת** (נשמר ב-`auth_sessions.json`, שורד אתחול). שינוי סיסמה מסיים את כל הסשנים.
- פעולות משנות-מצב דורשות גם אסימון CSRF (כותרת `X-CSRF-Token`) ומקור זהה.
- הגבלת ניסיונות: 5 כשלונות לכתובת ← נעילה ל-15 דקות; השהיה על כל כשלון.
- קישור עמוק מההתראה שורד את מסך הכניסה (נבדק בדפדפן).

### הגדרת הסיסמה — בלי שתופיע ביומן, בהיסטוריה או בצ׳אט

להריץ ב-PowerShell מתוך תיקיית הפרויקט. `--skip-deploys` מונע פריסה; הגרסה שבייצור כרגע בכלל לא קוראת את המשתנה.

```powershell
railway status                                   # לוודא שירות וסביבה נכונים
$s = Read-Host "Dashboard password" -AsSecureString
$p = [Runtime.InteropServices.Marshal]::PtrToStringBSTR([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s))
railway variable set "DASHBOARD_PASSWORD=$p" --skip-deploys | Out-Null
$r = -join ((1..48) | ForEach-Object { '{0:x2}' -f (Get-Random -Maximum 256) })
railway variable set "SESSION_SECRET=$r" --skip-deploys | Out-Null
railway variable set "TOMER_MANAGER_PHONE=972547598919" --skip-deploys | Out-Null
Remove-Variable s, p, r
# אימות בלי להציג ערכים:
$v = railway variable list --json | ConvertFrom-Json
"DASHBOARD_PASSWORD length: $($v.DASHBOARD_PASSWORD.Length) · SESSION_SECRET length: $($v.SESSION_SECRET.Length) · manager: $($v.TOMER_MANAGER_PHONE)"
```

לא להגדיר `ARBOX_WRITES_ENABLED`.

## 11. בדיקה חיה מבוקרת — אחרי פריסה, עם חבר/ת בדיקה מאושר/ת בלבד

1. "מה יש מחר?" ← פתיח תומר פעם אחת; מספרי רשומים תואמים ל-Arbox.
2. "לאיזה שיעורים אני רשומה השבוע?" ← תואם לאפליקציה; בלי פתיח חוזר.
3. "רוצה להקפיא את המנוי מ-X עד Y" ← "נרשמה… לא הוקפא"; **הודעה אחת** בוואטסאפ של המנהל עם קישור.
4. לחיצה על הקישור מהטלפון ← כניסה ← הפנייה נפתחת.
5. אותה בקשה שוב ← אין פנייה שנייה, אין התראה שנייה.
6. שיוך + תשובת צוות מהפאנל ← מגיעה לחבר/ה בלי פתיח תומר; הודעה נוספת של החבר/ה לא נענית אוטומטית ומופיעה בפנייה.
7. תשובה מהטלפון של הסטודיו ← תומר נשאר שקט.
8. "שחרר לתומר" ← שאלה חדשה נענית.
9. סגירה עם "הבקשה לא אושרה" + הערה. **בלי שינוי ב-Arbox.**
10. תמונה ← תומר מסביר שאינו רואה תמונות; פנייה אחת.
